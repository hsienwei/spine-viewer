# Share Feature UAT

本文件用來驗收目前已實作的分享流程，範圍以實際程式行為為準。

## 範圍

- 建立分享連結
- 開啟分享連結
- `Share History`
- `Revoke`
- `Delete from history`
- 24 小時過期
- 分享錯誤顯示
- Worker 清理後的失效行為

## 前置條件

- 已完成 Cloudflare `R2` 與 `KV` bindings 設定
- 可正常啟動本機或部署環境
- 準備一組可正常播放的 Spine 資產
- 至少包含：
  - `skeleton` 檔
  - `atlas` 檔
  - 一張以上 texture 圖片

## 驗收環境

- 本機開發：`npm run dev`
- 本機預覽：`npm run build` 後 `npm run preview`
- 正式驗收建議以部署環境為主，因為分享連結會依當前 origin 產生

## 基本驗收

### 1. 建立分享連結

步驟：

1. 載入一組可正常播放的 Spine 資產
2. 確認動畫可播放、切換
3. 點擊 `Share`

預期結果：

- 成功建立分享連結
- 側欄顯示 `Share link ready`
- 顯示到期時間
- 連結已自動複製到剪貼簿
- `Share History` 新增一筆紀錄
- 該筆狀態為 `Active`

### 2. 開啟分享連結

步驟：

1. 使用 `Open` 開啟剛建立的分享連結
2. 或將分享連結貼到新分頁開啟

預期結果：

- 路由進入 `/s/:token`
- 分享頁可正常載入 Spine 資產
- 動畫能播放
- 側欄顯示 `Shared preview`
- 顯示到期時間

### 3. 檢查分享資產處理

步驟：

1. 建立分享連結
2. 開啟分享頁
3. 觀察分享後畫面素材

預期結果：

- texture 已走分享資產流程
- 浮水印已烤進分享用 texture
- 浮水印為靜態文字型效果
- 視覺上可見，但不應嚴重破壞主要內容辨識

## Share History 驗收

### 4. Share History 顯示

步驟：

1. 建立一筆以上分享
2. 重新整理頁面

預期結果：

- `Share History` 仍可看到本機保存紀錄
- 紀錄依建立時間排序
- 每筆可看到：
  - 骨架檔名
  - 建立時間
  - 到期時間
  - 狀態

### 5. Active 狀態操作

步驟：

1. 找一筆 `Active` 紀錄
2. 測試 `Open`
3. 測試 `Copy`

預期結果：

- `Open` 可正常打開分享頁
- `Copy` 可複製分享連結
- `Revoke` 按鈕可操作
- `Delete` 按鈕可操作

### 6. Delete from history

步驟：

1. 對任一筆分享紀錄點擊 `Delete`

預期結果：

- 該筆紀錄從 `Share History` 消失
- 只影響本機歷史，不影響後端分享狀態
- 若直接使用原分享連結，仍應依其實際狀態決定是否可開啟

## Revoke 驗收

### 7. 撤銷分享連結

步驟：

1. 對一筆 `Active` 紀錄點擊 `Revoke`

預期結果：

- 該筆紀錄狀態改為 `Revoked`
- `Open`、`Copy`、`Revoke` 不可再操作
- `Delete` 仍可操作

### 8. 撤銷後重新開啟

步驟：

1. 開啟剛剛已 `Revoke` 的分享連結

預期結果：

- 無法載入分享內容
- 顯示 `Share load failed`
- 錯誤訊息應清楚表達此連結已被撤銷

## 過期驗收

### 9. 24 小時過期

步驟：

1. 建立分享連結
2. 等待超過 24 小時，或以測試方式建立過期資料
3. 重新開啟連結

預期結果：

- 無法載入分享內容
- 顯示 `Share load failed`
- 錯誤訊息應清楚表達此連結已過期
- `Share History` 狀態顯示為 `Expired`
- `Open`、`Copy`、`Revoke` 不可再操作

## 錯誤處理驗收

### 10. 不存在的 token

步驟：

1. 手動開啟不存在的 `/s/:token`

預期結果：

- 無法載入分享內容
- 顯示 `Share load failed`
- 錯誤訊息應清楚表達此連結不存在、不可用，或已被刪除

### 11. 資產缺失

步驟：

1. 使用測試方式讓 manifest 存在，但其中一個 asset 缺失
2. 開啟分享連結

預期結果：

- 無法完整載入分享內容
- 顯示清楚錯誤
- 錯誤訊息應指出有資產缺失或下載失敗

## Cleanup 驗收

### 12. 清理後的失效行為

步驟：

1. 建立分享
2. 將分享設為 `Revoked` 或等待其過期
3. 等待排程清理，或手動觸發 `/api/share/cleanup`
4. 重新測試原分享連結

預期結果：

- 連結仍應維持失效
- 前端不需要顯示 `cleanup` 狀態
- 使用者只需看到 `Revoked` 或 `Expired` 對應的失敗結果

## 回歸重點

每次調整分享功能後，至少重跑以下項目：

1. 建立分享連結
2. 開啟分享連結
3. 檢查靜態浮水印觀感
4. `Share History` 狀態與按鈕可用性
5. `Revoke`
6. 錯誤頁文案
7. `npm run build`

## 已知限制

- 分享接收者不需要登入
- 連結持有者在 24 小時內可直接開啟
- 無法真正防止有心人從瀏覽器取得資產
- 浮水印目前在前端預處理後再上傳
- `Share History` 儲存在本機瀏覽器，不會跨裝置同步
